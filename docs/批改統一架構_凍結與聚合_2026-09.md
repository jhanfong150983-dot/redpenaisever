# 批改統一架構：凍結與聚合（2026-09-04 user 拍板）

> 這份文件回答兩個問題：**重批時什麼要重跑、什麼直接沿用**（凍結），以及
> **評分統計怎麼把全班的作答分群**（聚合）。散在對話裡的拍板集中釘在這裡。

## 統一模型（目標架構）

```
第零層  老師人工改分 ─── 永久凍結，壓過一切（source='teacher'，AI 永不覆蓋）
第一路  文字：read 每次重跑 → 判分層凍結
          ├ 程式判得動 → code 確定性（天然凍結：同值必同分，連表都不用）
          └ 程式判不動 → 值→分數表（同值同分、跨學生共用）
第二路  圖像：判官看圖 → 同指紋一律冷凍（只對自己、跨重批）
```

兩種凍結的差別，一句話：**查表是「別人判過的我不用判」（鍵＝作答值），
冷凍是「我自己判過的不用再判」（鍵＝圖的指紋）。**

為什麼圖像路必須冷凍：LLM 服務端不保證可重現——VJ 實測 input_tokens 跨批次完全
相同、output 每輪都變；2026-08-31 沙盒也實證跨場次判官會漂（同圖同參數、隔幾小時
答案不同）。沒有冷凍＝每次重批分數可能翻盤（最傷老師信任）＋判官錢重付。

## 現況對照（2026-09-04 施工後）

### 第一路：文字

| 成員 | 判分 | 凍結 |
|---|---|---|
| 選擇／勾選／排序／克漏字／多選扣分／map_fill | code 確定性 | ✅ 天然凍結 |
| 國語註釋題（short_answer＋rubricsDimensions） | 值→分數表 | ✅ 值凍結、跨學生共用（命中 ~80%） |
| 一般文字題（fill_blank 等） | accessor | ⛔ **缺口**——重批重付、可能翻盤（見第四刀） |

### 第二路：圖像（判官）

| 判官 | 凍結 | 機制 |
|---|---|---|
| VJ 作圖三型 | ✅（2026-08-16） | `vj_verdict_cache`，鍵＝crop hash＋規準＋prompt 版本 |
| 字形判官 | ✅（**2026-09-04 本波**） | `judge_verdict_cache` kind='glyph' |
| 注音三判官 | ✅（本波） | kind='zhuyin'，鍵含**兩張圖**（學生＋答案卷標準圖） |
| 級分制 | ✅（本波） | kind='level'，鍵含全部 crop（寬圖切半＝兩張）＋levelRubric |
| rubric 判官 | ✅（本波） | kind='rubric'，鍵含 rubricsDimensions＋referenceAnswer |

共用模組：`server/ai/judge-verdict-cache.js`。設計要點：

- **圖 hash 一律 hash「實際送進模型的 bytes」**（放大後／畫紅框後）——裁圖或放大
  參數改動 → bytes 變 → 自然重判，不用另外管裁圖版本。
- **⚠ 動判官邏輯必改 `JUDGE_PROMPT_VERSIONS` 的版本號**，否則舊判定被沿用、新修法
  對既有卷無效——重批看起來成功、實際跑的是舊邏輯，比壞掉更難發現。
- fail-open：表不存在／查失敗 → 照舊跑判官。kill switch `JUDGE_FREEZE='0'`。
- 存凍用 `ignoreDuplicates`：`source='teacher'` 的列 AI 永不覆蓋（第零層在資料層的落實）。
- **fail-open 的判定（gVerdict 空）不入凍**——失敗要留給下次重試，不能凍住失敗。

DDL：`docs/ddl/2026-09-04_judge_verdict_cache.sql`（**要手動跑**；沒跑只是沒凍結效果，不會壞）。

## 聚合（評分統計的分群）

| 題類 | 分群依據 |
|---|---|
| 一般文字題 | 讀值文字 |
| 級分制 | `levelResult` 要素向量 |
| VJ 作圖 | `vjItemResults` 逐項向量 |
| compound_*（rubric 判官） | `rubricScores` 維度向量（判官沿用 accessor 同名契約） |
| 國字／注音 | ⛔ 無——讀值是佔位「圖像辨識」，`glyphVotes` 未接分群。單字題用對錯分佈已足，暫不做 |

⚠ 任何新判分管線都必須輸出**既有契約**的欄位（rubricScores／levelResult／vjItemResults），
不可自創平行欄位——rubric 判官第一版自創 `rubricDims`，聚合斷源＋補打閘門把判官的格
拉回 accessor，2026-09-04 修正（commit 578f036）。

## 第四刀（未做）：accessor 值凍結——把查表制推廣到一般文字題

全庫實測值重複率（＝值凍結的命中率上限；已排除佔位字串）：

| 領域×題型 | 題數 | 作答數 | 重複率 |
|---|---|---|---|
| 國語 fill_blank | 24 | 538 | **88%** |
| **數學 fill_blank** | **225** | **5,673** | **84%** |
| 國語 short_answer（註釋題，已在查表制） | 20 | 549 | 81% |
| 英語 fill_blank | 50 | 1,310 | 77% |
| 社會 fill_blank | 9 | 210 | 68% |
| 數學 short_answer | 5 | 126 | 22% |
| 社會 short_answer | 8 | 192 | 7% |
| 社會 compound_*（已走 rubric 判官） | 6 | 161 | **0%** |

判讀：
- **fill_blank 家族值域高度收斂（68–88%）**——值凍結划算。最大魚是數學 fill_blank
  （5,673 格），但其中大部分已被 code-first 確定性判掉（93–98%），accessor 只吃剩格；
  實作前要先量「真正到 accessor 的格」的量與重複率，別按全量估收益。
- 社會 short_answer（7%）與 compound_*（0%）值域不收斂——**這正是它們改走 rubric
  判官＋指紋凍結的原因**，兩路各得其所。
- 實作即「查表制推廣」：投票＋凍結＋scope 鍵沿用 semantic-score-table 的設計，
  範圍從「國語 short_answer＋rubricsDimensions」放寬到 fill_blank 家族。
